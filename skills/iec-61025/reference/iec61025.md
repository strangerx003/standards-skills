# IEC 61025:2006 — Fault Tree Analysis (FTA) — Full Reference

Source: IEC 61025, 2nd edition, 2006-12 (IEC TC 56 Dependability). Technical revision of the 1990 1st edition: added detailed FTA methodology explanations, quantitative/reliability aspects, expanded links to other dependability techniques, worked examples, updated symbols; former body material moved to Annexes A and B.

## 1. Scope
- Basic principles of FTA; mathematical modelling; relationships to other reliability techniques (FMEA, ETA, Markov, BDD, RBD); steps to perform an FTA; assumptions, events, failure modes; commonly used symbols.
- Normative references: IEC 60050-191 (dependability vocabulary), IEC 61165 (Markov techniques).

## 2. Two approaches
- **Method A — Qualitative FTA:** event probabilities not addressed (descriptive likelihood like "highly probable/medium/remote"); traces causes; primary goal = identify **minimal cut sets**. Nuclear heritage.
- **Method B — Quantitative FTA:** basic-event probabilities from analysis/test/field data; computes probabilities of all intermediate events and the top event; used for reliability improvement during development. Reliability shorthand also covers availability/maintainability.
- A fault tree can be developed as its complement, a **success tree**.

## 3. Terms
- **Top event:** single pre-defined event of interest at tree top.
- **Outcome:** event or state (gate output). **Primary events:** bottom of tree (basic or undeveloped).
- **Basic event:** lowest-level event with probability/reliability data. **Undeveloped event:** no further inputs (e.g. COTS).
- **Cut set / minimal cut set:** set of events causing the top; minimal = smallest, removal of any element prevents occurrence.
- **Single point failure:** occurs alone → top event.
- **Common cause events:** different events, same cause (e.g. ceramic capacitors shorted by PCB flexing).
- **Replicated/repeated event:** same event input to multiple higher-level events.

## 4. Symbols

### Event symbols
| Symbol | Meaning |
|---|---|
| Circle | Basic event (probability data available) |
| Conditional event | Condition for another event (used with PAND, INHIBIT) |
| Diamond | Undeveloped event (no further development needed/possible) |
| Dormant event | Latent failure, detectable only by inspection/test |
| House event | TRUE/FALSE switch, user-controlled branch inclusion |
| Transfer IN/OUT | Tree continues elsewhere (same label mandatory) |
| Zero event | Event that cannot happen |

### Static gates (output not sequence-dependent)
| Gate | Behaviour | Formula (independent inputs) |
|---|---|---|
| OR | ≥2 inputs | F_S = 1 − ∏(1 − F_i); success = series system |
| AND | ≥2 | F_S = ∏ F_i; success = parallel redundancy |
| Majority vote (m-of-n) | m = n − k + 1 | F_S = Σ_{i=0}^{k−1} C(n,i) F^i (1−F)^{n−i} (identical inputs); e.g. "3 of 6" → vote m = 4 |
| NOT | 1 input | F = 1 − F₁ — use with care (experienced analysts only) |
| XOR | exactly 2 | F = F₁ + F₂ − 2F₁F₂ |
| NOR | ≥2 | NOT+OR; output none occur — use with care |
| NAND | ≥2 | NOT+AND — use with care |
| INHIBIT | 2 inputs incl. conditional | output = input prob × condition prob |

### Dynamic gates (output depends on input ORDER; need Markov/simulation per IEC 61165)
- **PAND (Priority AND):** output only if inputs occur left→right in sequence; >2 inputs ≈ SEQ gate.
- **SEQ (Sequential):** chain failures; >2 inputs.
- **SPARE:** standby redundancy (cold/warm/hot); exponential distributions may give closed form, otherwise Markov/simulation.

## 5. Objectives of FTA (5.2)
Identify cause combinations; verify reliability requirements; find highest contributors; compare design alternatives; validate assumptions of Markov/FMEA; identify safety-relevant failure modes; identify common events; prioritise contributors; assess event importance/impact; compute probabilities, availabilities, failure rates (steady state, independent repairs only).

## 6. Applications & combinations
- Systems with functionally related subsystems; multiple design groups (separate trees linked); nuclear, transport, comms, chemical, railway, medical, consumer, computers; mixed mechanical/electronic/software interactions.
- **FTA + FMEA (IEC 60812):** deductive + inductive completeness; every FMEA single failure reaching the top event must appear as a single-point failure in a minimal cut set. Best performed independently (esp. safety). Do both per IEC 60300-3-1.
- **FTA + ETA:** reduced top events become event-tree inputs → cause-consequence analysis (CCA).
- **FTA + Markov:** dynamic gates evaluated by Markov, replaced by one primary event with computed probability.
- **FTA + BDD:** exact computation, no truncation error; exact importance/sensitivity from disjoint minimal paths.
- **FTA + RBD (IEC 61078):** blocks with internal interactions modelled by FTA; probability assigned to RBD block.
- Applicable in all design phases, evolving with design ("analysis concurrent with design"); software packages needed for large trees.

## 7. Development and evaluation (Clause 6–7)
- **Events vs states:** AND-gate inputs to an *event* must all be events; if outcome is a *state*, inputs are states. States use time-t probability; events use frequency/rate.
- **Required system info (6.2):** design intent, failure definition, functional structure, boundaries/interfaces, physical structure, operational modes/profile, environment, human aspects, mission duration, test intervals, maintenance, support, applicable documents, phase functions.
- **Minimum procedure:** scope → familiarize → top event → construct → analyse logic → report → assess improvements.
- **Personnel:** detailed system knowledge + FTA/reliability training; root review by design team; corrective actions documented and followed up. (The core quality requirement.)
- **Construction (7.5.3):** define top event, scope, boundaries, **resolution** (down to component or assembly level matched to probability data). Then immediate-cause concept (mechanism/mode, not root cause) down to the "basic unit" (clear functional/physical boundaries, no support dependency, no further immediate causes).
- **Evaluation (7.5.4):** investigation (against drawings/doct; find common events, independent branches) → Boolean reduction → minimal cut set identification (computer programs for large trees) → numerical analysis with component probabilistic data. Cut sets only exist for static gates (approximation if sequencing ignored).
- **Worked example (7.5.5) — bridge circuit A,B,C,D with cross-bridge E:** minimal cut sets {a·b, c·d, a·e·d, b·e·c}. Esary-Proschan F = 1−∏(1−Pr(c_i)) is approximate; rare-event approximation ΣPr(c_i) can exceed 1 for large probabilities; **disjointing (Annex B)** gives the exact value.
- **Failure rates (7.6):** usable with Poisson/constant-rate assumption; convert rates to probabilities for mixed trees; repairable systems out of scope.

## 8. Identification and labelling (Clause 8)
- Every event uniquely identified; labels cross-reference design documentation; exactly one top event per tree.
- Different failure modes of same item distinguishable but grouped; removed/duplicate-label events forbidden in software — reuse identical labels for repeated/common-cause events.
- Typical code: subsystem + component + failure mode, e.g. `Short_C132`, `Short_A_C135`, `Open_R34`, `Low_Output_U2`.
- Labels must match exactly between spreadsheets and FTA tools.

## 9. Report (Clause 9)
Minimum: objective and scope; system description with boundaries; assumptions (design, operation/maintenance, modelling); analysts + top-event criteria; data sources and justification of primary/undeveloped event probabilities; analysis description (symbols, common-cause failures, minimal cut sets); results, conclusions, recommendations. Optional: diagrams, data summaries, FMEA/FMECA or reference.

## Annex A — Symbols
Event symbol tables, static/dynamic gate tables (above), plus a PAND example: diode D1 protecting an IC — "IC explodes" only if diode fails open *then* voltage surge occurs → PAND, Markov needed.

## Annex B — Disjointing procedure
Algebraic algorithm making each minimal cut set disjoint w.r.t. all preceding terms via relative complements (e.g., expand bd → abd + ābd). Yields exact probability as sum of disjoint products; term order affects intermediate form but not the value.

## Known limitations / gotchas
- No formal importance-measure clause (no Fussell-Vesely/Birnbaum definitions) — see IEC 60300-3-1 or NASA FTA handbook for those.
- No probability-data selection guidance, no repairable-system FTA, no software recommendations.
- OCR of complement (NOT) overbars is unreliable — verify NOT/NAND/NOR/XOR formulas against a clean copy for precision.
- Bibliography: NUREG-0492, NASA Fault Tree Handbook v1.1, Modarres et al., IEC 60812, IEC 61078, IEC 61165.
